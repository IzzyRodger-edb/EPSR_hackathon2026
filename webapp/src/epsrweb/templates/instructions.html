Instructions

What to upload, what happens to it, how to read the results, and how to get the figures into your paper.

1. What to upload

Gudrun .mint01 files: plain text, three whitespace-separated columns.

ColumnQuantityUnits
1QA-1
2differential cross section, F(Q)barn sr-1 atom-1
3the error on F(Q)as column 2
  • Header lines start with #, and the second one is the sample title — that is the string the agent reads to recognise the sample (H2O, D2O, HDO, SiO2, benzene, DMSO, Cu-BTC).
  • Upload every isotopic sample of one material together, in one run. Two to four files is typical. They are what makes the refinement well determined; one file alone will fit, but it will not be a determination of the partials.
  • Add a sentence in the prompt box if the titles do not say what the material is: composition, temperature, density.
  • Files are checked on upload, before anything is queued. Rejections mean the file is not a three-column table. Warnings are kept and shown in the log — the common ones are data extending past 30 A-1 (silently discarded, because EPSR interpolates onto nq 600 × qstep 0.05) and a missing zero sentinel row (EPSR treats Q as a bin edge and drops the last point).
  • Do not worry about the file name: blanks and awkward characters are rewritten, because EPSR truncates a data path at the first blank.

Raw detector data is not an input. .mint01 is the output of Gudrun's correction chain — attenuation, multiple scattering, vanadium normalisation, inelasticity, self-scattering subtraction. If you have raw NeXus files, reduce them first.

2. Choosing how the model system is decided

Automatic / hosted model
The agent inspects your data and proposes the model system: molecule geometry, force field, composition, density and the isotopic substitution scheme. For a material in its validated library (water, silica, DMSO/water, benzene, Cu-BTC) it adapts the validated one; otherwise it proposes a new one, which the report marks unvalidated.
No language model
Pick a validated system from the list and skip the model entirely. Deterministic, free, and the right choice when your material is one of those five, or when you want a baseline to compare an agent-proposed run against.
Local model
Only if the server has a GPU with about 8.4 GB free.

3. What happens while you wait

  1. The data is validated and the run gets a folder of its own.
  2. The specification is chosen, the EPSR inputs and a standalone script are generated.
  3. The engine runs three stages: a scratch start, an equilibration on the reference potential with the EP switched off, then refinement with the empirical potential on.
  4. Figures, CSV tables, analysis.json and the PDF report are written.

The quick schedule (10 iterations per stage) takes a minute or two and is for previews only — it does not converge. The full schedule (99 + 2 × 100 iterations) is about ten minutes for water on a 20-core machine.

You can close the page. The job runs in its own process; the results page replays the whole log when you return. Stop kills that process and keeps the partial folder.

4. Reading the results

The fit (02_fq_fit, sb_fit_overlay)
Measured against simulated F(Q) for each sample, with the difference. Look at where in Q the misfit is. Below about 2 A-1 in hydrogenous samples it is usually inelasticity, which EPSR cannot fit; a misfit at the first sharp peak is a density or a geometry problem.
R-factor
A few times 10-4 for a liquid against good neutron data (water: 2.3 × 10-4). Near 10-2 for a crystal modelled with intermolecular bonds only. R squared near 1 means the fit follows the data.
Convergence (01_convergence, sb_convergence)
R-factor and energy should plateau; the EP amplitude should rise and then settle. Still rising means it needs more iterations. EP amplitude at ereq means the cap is binding: a larger ereq may fit better, but a large EP says the reference potential is poor.
Partials (05_partials, sb_partials)
First-peak positions are bond or neighbour distances: water O···H 1.8 A, O···O 2.8 A; silica Si–O 1.59 A. Coordination numbers count neighbours within the first minimum.
Potentials (06_potentials, sb_potentials)
The empirical potential should be a correction, small next to the reference potential. If it dominates, treat the structure with suspicion.

The Numbers tab is analysis.json: fit quality per data set, the stages, the first-shell table, and any flags the analysis raised. The Files tab has the long-format CSV tables, which pandas reads directly if you want to plot something yourself.

5. Checking it yourself

Every run folder contains run_<name>.py, a standalone script with every input file embedded. It reproduces the refinement with only the open-source wrapper and toolkit — no language model: 

python run_water.py --out DIR

EPSR runs with EPSR's defaults throughout: nq 600, qstep 0.05, ntimes 5, feedback 0.9.

6. Getting the figures into Overleaf

  1. In Overleaf: Account Settings → Git integration, create a Git authentication token. This is a premium feature; if your account does not have it, skip to step 5.
  2. Copy your project's URL from the address bar and paste both it and the token into Settings. The token is encrypted at rest and never logged.
  3. On a results page, open Figures, tick what you want, choose PDF where available (vector, which is what you want in a paper) and press Push to Overleaf.
  4. The figures land in figures/ in your project, named <run id>_<figure>.pdf so two runs cannot overwrite each other. The app shows you a ready-made block to paste: 
    \begin{figure}[htbp]
  \centering
  \includegraphics[width=\linewidth]{figures/20261017-120000-ab12cd_sb_fit_overlay.pdf}
  \caption{Measured and simulated structure factor ...}
  \label{fig:20261017-120000-ab12cd_sb_fit_overlay}
\end{figure}
    If someone edited the project in the browser meanwhile, the push rebases once and retries.
  5. Without premium: Download zip gives you the same figures plus a figures.tex containing those blocks. Drag the folder into the Overleaf file tree. (If your project is already synchronised with GitHub, pushing to that repository's figures/ folder and pulling in Overleaf works too.)

7. Limits worth knowing

  • A model system outside the library is a proposal, not a validated model. Check the force-field parameters in spec.json before you publish anything from it.
  • The quick schedule does not converge. Do not quote numbers from it.
  • Asking the agent to run a new refinement in the chat overwrites this run's results. Start a new run instead.
  • One run at a time per account by default: a refinement uses every core.
  • A full run is a few hundred megabytes, most of it the per-iteration trajectory. Delete runs you no longer need; deleting removes the whole folder.
